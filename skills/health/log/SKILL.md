# Health Log

筋トレ・食事・体重の記録だけを担当する。**分析と助言は `health-today` の仕事**なので、
このスキルでは数値の評価をしない。

## When to Use

ユーザーが**実際にやったこと・食べたこと**を報告したとき。

- 「ベンチ40キロ8回3セット」「ラットプルダウン47キロ10回×3」
- 「昼はパン3つ食べた」「カフェラテ350mlとワッフル」
- 「体重64.2」
- **「8/25は朝おにぎり2つ、昼は弁当」「昨日はデッドリフト42.5キロ8回8回7回」**
  （日付つき。数日分まとめて報告されることがある）
- `bp 40 8,8,8` `w 64.2` `m サラダチキン` のような定型
- 「さっきの取り消して」

使わない: 「あと何食べればいい？」「今日何すればいい？」（→ `health-today`）、
週の振り返り（→ `health-report`）。

## Quick Reference

| 目的 | コマンド |
|---|---|
| 筋トレ（同一重量） | `health bp 40 8,8,8` |
| 筋トレ（セット別重量） | `health bp 40x8,37.5x8,35x6` |
| 自重種目 | `health pu 5,4,3` |
| 体重 | `health w 64.2` / `health w 64.2 15.3`（体脂肪率つき） |
| 食事（定型） | `health m サラダチキン, おにぎり*2` |
| **自由文（API キーあり）** | `health nl "8/25は朝おにぎり2つ。ベンチ40キロ8回8回6回。65.2キロ"` |
| **自由文（API キーなし）** | `health batch <<'EOF' ... EOF` に複数行を流す |
| マスタに食品を足す | `food <名前> \| <単位> \| <kcal> <P> <F> <C> \| <種別> \| <別名>`（batch 内） |
| マスタに種目を足す | `ex <コード> \| <名前> \| <部位> \| <push\|pull\|legs>`（batch 内） |
| **遡って記録** | どの記録コマンドにも `--date 8/25`（`昨日` `3日前` `先週の火曜` も可） |
| メニュー表示 | `health t pull` |
| 直前を取り消す | `health undo` |
| 直近の記録 | `health last` |

種目コード: `bp`ベンチプレス `sq`スクワット `dl`デッドリフト `lpd`ラットプルダウン
`row`ローイング `sp`ショルダープレス `sr`サイドレイズ `dbc`ダンベルカール
`lpr`レッグプレス `pu`懸垂。全一覧は `health t push|pull|legs`。

## Procedure

1. **入力が既に定型なら、解釈せずそのまま実行する。**

   先頭が種目コード / `w` / `m` / `t` / `undo` / `last` で始まっていれば、
   **考えずに `health <入力そのまま>` を実行して結果を返す。**
   これが最も安く速い経路で、モデルの判断を一切挟まない。

2. **定型でなければ、発言まるごと自由文の経路に渡す。**

   食事・筋トレ・体重・日付が混ざっていても分解しない。**1回で渡す。**
   自分で栄養価を計算しない、日付を計算しない、種目コードに直さない。
   マスタと規則で解決するのは CLI 側の仕事。

   **`ANTHROPIC_API_KEY` があるなら:**

   ```
   health nl "8/25は朝おにぎり2つ、昼は惣菜弁当。ベンチ40キロ8回8回6回。65.2キロ"
   ```

   **無いなら `batch` に組み立てて渡す。** `nl` はキーが無いとエラーで落ちるので、
   キーの有無が分からないなら `batch` を既定にする。
   マスタに無い品・種目は `food` / `ex` 行を先に置く。**SQL で足さない。**

   ```
   health batch <<'EOF'
   food 惣菜弁当 | 個 | 650 20 20 92 | dish | 総菜弁当
   --date 8/25 bp 40 8,8,6
   --date 8/25 m 12:30 惣菜弁当
   EOF
   ```

3. **日付が書かれていなければ何もしない。** `nl` が今日として記録する。
   `--date` を足すのは、**ユーザーが日付を言ったのに `nl` が拾い損ねたとき**だけ。
   文中に日付があるものを `--date` で上書きすると、書いたほうが無視されて事故になる。

4. **発言を複数のコマンドに割らない。** `nl` も `batch` も、1回の入力で複数日・
   複数テーブルに書き分け、**それ全部を1回の `health undo` で消せる**ようにしている。
   `health` を何回も別々に呼ぶと、この取り消し単位が壊れる。

5. 実行結果を**1行以上必ず返す**。無反応が最悪で、入ったか分からないと
   次から投げてもらえなくなる。

6. **食事を記録したときは、続けて `health today` を実行して残りを1行添える。**
   「あと 1,400kcal / タンパク質 45g」の形。ユーザーが毎回
   「どれくらい足りない？」と聞き返す手間と、その分の1往復を省くため。
   筋トレと体重の記録では添えない（残りの話と関係ないので）。

7. `!` の警告と `?` の確認は、**省略せず全部そのまま伝える。**
   特にこの4つは黙って通すと数値が静かにずれる:

   - 「マスタに無いので栄養価0で記録」
   - 「複数該当したので○○にした」
   - 「マスタに追加（source='llm'）」— 推定値なので実物のラベルで直す必要がある
   - 「種目○○はマスタに無いので記録しなかった」— **記録が落ちている**ので必ず伝える

8. Discord では2000文字を超えると分割される。**出力は10行以内に収める。**
   表は使わない（スマホで崩れる）。

## Pitfalls

- **`health` が PATH に無い。** 先に `ln -sf <repo>/skills/health/bin/health ~/.local/bin/health`
  を実行しておく。`${HERMES_SKILL_DIR}` からの相対パスは、開発用シンボリックリンク経由だと
  リンク先ではなくリンク元を指すので使わない。
- **DB が無い。** `health init` と `health import` が済んでいるか確認する。
- **栄養価を自分で計算しない。** マスタの値を使わないと、同じ食品の記録が日によってずれる。
- **記録をエラーで止めない。** マスタに無い食品は栄養価0の「未知」として通る仕様。
  それが正しい挙動なので、名前を勝手に別の品に置き換えない。
- 曖昧な量（「パン3つ」の種類、「プロテイン」の製品）は `nl` が `?` 付きで報告する。
  それをユーザーに転送する。こちらで決めない。
- **同じ日に `w` を2回打つと上書きになる。** 警告が出るのでそれも伝える。
  **上書き後の `undo` は元の値を復元せず行を消す**ので、消すのではなく入れ直す。
- **DB を直接 SQL で触らない。** `undo` が効かなくなり、記録が汚れても戻せない。
  遡るなら `--date`、食品・種目を足すなら `batch` の `food` / `ex` 行を使う。
  この2つで SQL を叩く理由は無くなっている。
- **`batch` で読めなかった行は必ず伝える。** 終了コードが1になり、
  行番号付きで stderr に出る。**その行の記録は落ちている**ので黙って通さない。

## Verification

`health last` に今入れた記録が出ること。
食事なら `health today` の摂取量が増えていること。
