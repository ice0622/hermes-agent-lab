# 健康管理エージェント

仕様: `docs/spec/health-agent.md` / 実装計画: `docs/plan.md`

**Hermes は不要。** 記録・集計・診断は CLI と SQLite だけで動き、LLM を使わない。

自由文で記録したいときの経路は2つある。**どちらも役割分担は同じ**で、
違うのは「LLM を誰が呼ぶか」だけ。

| 経路 | LLM を呼ぶ主体 | 必要なもの |
|---|---|---|
| **`health prompt` + `health batch`** | **ブラウザの Claude**（人が貼る） | なし。**API キー不要** |
| `health nl` | CLI が API を呼ぶ | `ANTHROPIC_API_KEY` |

## セットアップ

```bash
# DB を作ってマスタを入れる（既定: ~/health/health.db）
./skills/health/bin/health init

# 手書き記録1年分を投入。初日からグラフが出る状態にする
./skills/health/bin/health import
```

DB の場所は環境変数 `HEALTH_DB` で変えられる。

```bash
export HEALTH_DB=/tmp/test/health.db   # 試すとき
```

PATH に入れておくと楽。

```bash
ln -sf "$PWD/skills/health/bin/health" ~/.local/bin/health
```

## 記録

```bash
health t                      久しぶりの分割のメニューを出す
health t push                 分割を指定
health 1 60 8,8,7             メニューの番号で種目を指定
health bp 60 8,8,7            種目コードで指定（同一重量 × 8/8/7）
health bp 60x8,60x8,55x7      セットごとに重量が違う場合
health pu 5,4,3               自重種目
health w 64.2                 体重
health w 64.2 15.3            体重 + 体脂肪率
health m サラダチキン, おにぎり*2   食事（カンマ区切り）
health m 12:30 牛丼            時刻を明示
health undo                   直前の記録を取り消す
health last                   直近の記録を確認
```

数量は `*2` `x2` `×2` `:2` `2個` `2本` `2枚` `2杯` などに対応する。

### 日付（`--date`）

**記録コマンドはすべて `--date` を受ける。省略すれば今日。**

```bash
health w 65.2 --date 8/25
health dl 42.5 8,8,7 --date 昨日
health m 19:00 惣菜弁当 --date 3日前
```

解釈できる書き方: `8/25` `8-25` `8月25日` `25日` `2026-08-25` `今日` `昨日` `おととい`
`3日前` `火曜`（直近の過去の火曜） `先週の火曜`。全角も通る。

- **年の無い `8/25` が未来になったら去年と読む。** 記録は過去に対して行うもので、
  未来の記録は存在しない。補正したことは警告で出す
- **日付が読めなくても記録は止めない。** 今日として入れ、警告に回す
  （入力がエラーで弾かれると、その日から記録をやめる）
- 遡って入れた記録の時刻は `00:00`。当日は現在時刻。
  今日の記録の順序を失わないため

## 貼り付け経路（`prompt` + `batch`）— API キー不要

**API キーが無くても自由文で記録できる。** ブラウザの Claude に変換させて、
返ってきたブロックを端末に貼る。

### 1回だけ: プロンプトを渡す

```bash
health prompt > ~/health/master.md
```

これを claude.ai の **Project に添付**しておくと、毎回貼らなくて済む。
中身はマスタ（食品・種目の全一覧）と書式の指示。約12KB。
**マスタに品や種目が増えたら出し直して差し替える。**

### 毎回: 自由文で報告して、返ってきたブロックを貼る

ブラウザで「8/25は朝おにぎり2つ、昼は惣菜弁当。ベンチ40キロ8回8回6回。65.2キロ」と
書くと、そのまま端末に貼れるブロックが返る。

```bash
health batch <<'EOF'
--date 8/25 bp 40 8,8,6 --note 呼吸を意識する
--date 8/25 w 65.2
--date 8/25 m 08:00 おにぎり（鮭）*2, 納豆
--date 8/25 m 19:00 惣菜弁当
EOF
```

**記録行の書式は上の CLI とまったく同じ。** 新しい構文は `food` と `ex` の2つだけ。

```
food コンビニ豚焼き肉弁当 | 個 | 700 24 22 97 | dish | 豚焼肉弁当
ex   hip | ヒップスラスト | 臀部 | legs
```

マスタに無い品や種目を、記録と同じ貼り付けの中で足せる（**足した直後の行から使える**）。
これが無かったので `foods` を SQL で直叩きするしかなく、`undo` が効かなくなっていた。

### 約束

- **1行が失敗しても止めない。** 通った行は記録し、失敗した行だけ行番号付きで報告する。
  1行のミスで全部やり直しになると、貼り直すのが面倒で記録をやめる
- **貼り付け1回 = `health undo` 1回。** どこまで戻したか分からなくなるのを避ける
- `food` は既にある品を**上書きしない**（実物のラベルで直した値を潰さないため）
- ファイルからも読める: `health batch day.txt`

## 自由入力（`nl`）— API キーがあるとき

固い書式を思い出せないときはこちら。**食事・筋トレ・体重・日付をまとめて受け付ける。**

```bash
health nl "8/25は朝おにぎり2つ、昼は惣菜弁当。ベンチ40キロ8回8回6回。65.2キロ"
```

```
記録 [2026-08-25]: ベンチプレス  40kg×8, 40kg×8, 40kg×6  （3セット）
記録 [2026-08-25]: おにぎり（鮭）×2  →  360kcal / P 10g
記録 [2026-08-25]: 惣菜弁当×1  →  650kcal / P 20g
記録 [2026-08-25]: 体重 65.2kg
  取り消す場合は health undo（今入れた分すべて）
```

- **日付を書かなければ今日。** 1つの入力に複数の日が混ざってもよい
  （「8/25は〜、昨日は〜」→ 日ごとに分けて記録する）
- マスタにある品はマスタの値を使う（`claude-haiku-4-5` に名前を突き合わせさせるだけ）
- **マスタに無い品は栄養価を推定して `foods` に `source='llm'` で追記する。**
  二度目以降はマスタ参照だけで済み、API を呼ばない
- **種目はマスタに無ければ記録しない。** 分割（push/pull/legs）の割り当てが
  集計に効くので勝手に増やさない。`?` で報告するので `seed_exercises.sql` に足す
- 量や種類が判別できなかった点は最後に `?` 付きで報告する
- **1回の入力で入ったものは、1回の `health undo` でまとめて消える**
  （食事・筋トレ・体重が同時に入るので、1件ずつしか消せないと入れ直しが当てものになる）

### どこまでを LLM に任せているか

| 仕事 | 担当 |
|---|---|
| 品名・種目名・数量の抽出 | LLM |
| 日付の**表記の抽出**（「先週の火曜」がどこにあるか） | LLM |
| 日付の**計算** | `lib/dates.py`（規則。LLM を通さない） |
| 種目名 → 種目ID、既知食品の栄養価 | `lib/resolve.py`（DB が唯一の真実） |
| 未知食品の栄養価の推定 | LLM |

**日付計算をモデルにやらせない。** 「先週の火曜」の解釈が実行日でずれると、
同じ入力が別の日付に入って記録が信用できなくなる。

**この表は貼り付け経路（`batch`）でも同じ。** LLM がブラウザ側に移るだけで、
日付計算とマスタ解決は `dates.py` / `resolve.py` を通る。

定型で打てるなら定型のほうが速く、しかも無料（`bp 40 8,8,6` は LLM を通らない）。

準備（この環境には `pip` が無いので `uv` を使う）:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
uv venv .venv && uv pip install --python .venv/bin/python anthropic
export ANTHROPIC_API_KEY=sk-ant-...
```

`.venv` はリポジトリ直下に置く。`bin/health` が自動で見つける。
**Anthropic Console で spend limit を先に設定すること。**

## 確認と診断

```bash
health today                  今日の摂取と残り
health check                  問題点と次のアクション
health check --apply          提案された目標カロリーの変更を適用
health report                 dashboard.html を生成（一覧・グラフ）
```

`health report` は `~/health/dashboard.html` を1ファイル書き出す。
**常駐プロセスなし、JavaScript なし、外部読み込みなし。** ブラウザで開くだけ。

載っているもの:

- 体重（日々の実測 + 週平均）と月平均の表
- 今日の摂取 vs 目標（超過は網掛け）
- 主要4種目の推定1RM推移
- 月ごとのトレーニング日数
- 直近12セッションの一覧（種目・重量・レップ・総挙上重量）
- タンパク質の供給源トップ8（直近30日）

配色はモノクロ。単一系列のグラフしか使っていないので配色で情報を持たせていない。
2系列になる体重グラフだけ、色ではなく**マークの形**（点と太線）で区別して凡例を付けている。
`prefers-color-scheme: dark` に対応（自動反転ではなく暗い面向けに選び直した階調）。

## 設計上の約束

- **記録は止めない。** マスタに無い食品でも栄養価 0 の「未知」として記録し、
  `health check` が後で報告する。入力がエラーで弾かれると、その日から記録をやめる
- **定型入力は LLM を通さない。** 正規表現とマスタ参照だけ。
  `bp 60 8,8,7` は自然言語より速く打てて、しかも無料。
  自由入力（`nl`）でも、**抽出だけを LLM にやらせ、日付計算とマスタ解決は規則で行う**
- **診断は必ず「次のアクション」を1つ付ける。** 問題の指摘だけでは行動が変わらない
- **記録が無いときは他の分析を出さない。** 前提の無い分析はノイズになる。
  記録が続いていないときは、目標ではなく**入力形式（手段）を疑う**
- **目標値は固定しない。** 体重の週平均で毎週補正する（`health check`）。
  TDEE の推定式には ±10% の誤差があるため

```
skills/health/

├── db/
│   ├── schema.sql          7テーブル + ビュー4つ

│   ├── dates.py            日付表現の解決（LLM を通さない）

│   └── history.py          手書き記録（Markdown）の取り込み

```

## 既知の制約

- `sqlite3` CLI はこの環境に無い。DB は Python の `sqlite3` モジュール経由で触る
- `foods` の30品は全て `source='estimate'` の暫定値。**初回に買ったとき実物の
  栄養成分表示を見て `'label'` に更新する。** 暫定値のままだと「摂取不足」の判定が信用できない
- 判読不能で未登録の種目2件（`LATERAL LOW` / `シーテッド`）は取り込み時にスキップされる
- **同じ日の体重を上書きしたあとの `undo` は、上書き前の値を復元せず行を消す。**
  `body` は日付が UNIQUE で UPSERT しているため、元の値がどこにも残っていない。
  上書きの警告が出たら、消すのではなく正しい値で入れ直す
- **`nl` が `foods` に追記した品は `undo` では消えない。** 記録だけが取り消される。
  マスタの充実は記録とは別の話で、消すと次回また API を呼ぶことになる。
  推定値が間違っていたら `foods` を直接直す
