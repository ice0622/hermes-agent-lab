# Grill Me

設計相談ではなく詰問。ユーザーの構想の弱いところを突いて、実装可能な粒度まで落とす。
成果物は会話ではなく `docs/spec/<slug>.md` の1ファイル。

## When to Use

- ユーザーの手元にあるのが「〜なアシスタントが欲しい」レベルの構想だけのとき
- 仕様の方針そのものを決める段階のとき
- ユーザーが `/grill-me` を明示的に呼んだとき

使わない: 仕様が既に決まっているタスク、コードレビュー、単なるブレインストーミング。
アイデアを増やすスキルではない。**減らして1つに絞る**スキル。

## 原則

1. **一問ずつ。** 最大2問。並べると全部に薄く答えられて何も決まらない。
2. 質問は必ず **数字・固有名・日付・トレードオフ** のどれかを引き出す形にする。
3. 抽象名詞（効率化・快適・便利・最適化・スマートに）が答えに出たら、**観測可能な事象に翻訳させるまで次に進まない**。
4. ユーザーの答えを要約して返さない。相槌も同意もいらない。次の質問に使う。
5. 自分で調べられることは聞かない。リポジトリ・`git log`・設定ファイル・実際のインストール状況を先に見る。
6. 逃げ道を作らない。「どちらでもいい」と言われたら**こちらが決めて理由を1行で示し**、反論を待つ。
7. 矛盾を見つけたらその場で指摘する。前の回答と噛み合わない答えを通さない。
8. 褒めない。ただし人格ではなく構想を撃つ。撃つ先を間違えない。

## Procedure

0. **対象の確定。** 何について詰めるのかを1行で固定する。リポジトリの現状は1回だけ調べる（何が既にあり、何が動いていないか）。以降は調べ直さない。

1. **ラウンド1 — 成功の定義。**
   「これが上手くいったとき、あなたの1日のどの瞬間が、どう変わっているか」
   観測可能な文になるまで粘る。「楽になる」は答えではない。

2. **ラウンド2 — 現状の実測。**
   今の数字を出させる。持っていなければ、**測ることがタスク1**になる。
   推測値と実測値を混ぜさせない。混ざったら「それは測った数字か」と聞く。

3. **ラウンド3 — 制約。**
   常時稼働できるマシンがあるか / 週に割ける時間 / 払える金額 / 絶対に変えられないもの。
   ここで多くの構想が死ぬので早めに置く。後回しにすると作ったものが動かない。

4. **ラウンド4 — 最小の一撃。**
   1週間で作れて、その後**毎日使うもの**を1つ。複数出たら1つに絞らせる。
   「まず全部の土台を作る」は却下する。土台は2つ目を作るときに初めて形が分かる。

5. **ラウンド5 — 撤退条件。**
   「N日後に〜になっていなければ捨てる」の形。日付か回数が入らない撤退条件は無効。

6. **書き出し。** `docs/spec/<slug>.md` に次の見出しで書く。
   `## 動機`（1行）/ `## 成功の定義` / `## 現状の実測` / `## 制約` / `## 決定` / `## 未決` / `## 次の一手` / `## 却下（理由つき）`

7. 未決が残っていても書く。空欄は `未決` に置いたまま出す。**空欄を埋めることより着手が優先。**

## 質問の型

| 悪い質問 | 良い質問 |
|---|---|
| 優先順位はどれですか | AとBのどちらか片方しか動かないとしたら、無いと困るのはどっち |
| どんな機能が欲しいですか | 昨日それがあったら、実際に手が止まっていた瞬間はどこ |
| 目的は何ですか | 完成した3ヶ月後、あなたが**していない**ことは何 |
| 使いやすくしたいですか | 起動に30秒かかるなら使うか。かかっても使う理由は何 |
| どのくらいの頻度で使いますか | 直近7日で、それを必要とした回数は |

型は「未来の願望」ではなく「過去の実測」を聞く方向に寄せる。願望は無限に出るが、実測は有限。

## Pitfalls

- **質問を並べる。** 最大の失敗。全問に一言ずつ返ってきて、決まったことがゼロになる。
- **熱い語りを仕様として記録する。** 熱量は動機。動機は1行だけメモして、観測可能な指標に戻す。
- **「とりあえず全部」を許す。** 必ず途中で止まる。止まった残骸は次の着手を重くする。
- **詰問の自己目的化。** ラウンド5まで来たら書き出しに移る。もっと聞けることは常に残っている。
- **`AskUserQuestion` の乱用。** 選択肢が2〜4個に本当に絞れる時だけ。開いた問いは素のテキストで聞く。選択肢を出すと、こちらの想定の中からしか答えが返らない。
- **調査で時間を潰す。** これは調査スキルではない。手を動かす前に決めるためのもの。

## Verification

`docs/spec/<slug>.md` が存在し、次のすべてを満たす。

- 「成功の定義」が観測可能な文で書かれている（副詞ではなく事象）
- 「現状の実測」に数字がある。または「未測定 → 測るのがタスク1」と明記されている
- 「撤退条件」に日付か回数が入っている
- 「次の一手」が**1つだけ**で、1週間以内に終わる大きさ
- 「却下」に、捨てた案と捨てた理由が残っている（後で蒸し返さないため）
