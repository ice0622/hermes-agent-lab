# 入出力の設計 — Discord で完結させる

作成 2026-08-25 / 前提: `docs/spec/health-agent.md`, `docs/plan.md`

---

## 出発点: 今の実装で Hermes は何もしていない

事実を先に置く。

```
$ grep -rl "hermes" skills/health/     → 0件
$ find skills/health -name SKILL.md    → 0個
$ health CLI の依存                     → 標準ライブラリのみ（nl だけ anthropic SDK）
```

フェーズ0を「Hermes なし・LLM なし」で切り出した結果、**動くものができた時点で
Hermes の役割が消えていた**。これは設計ミスではなく、順序として正しかったが、
「では Hermes は何なのか」を決め直す必要がある。

## Hermes が実際に提供するもの

| 機能 | このプロジェクトで必要か |
|---|---|
| **ゲートウェイ**（Discord/Telegram/Slack/…20以上、送受信の両方） | **必要。** Discord で完結させるなら中核 |
| **cron / blueprint**（定時実行 + 任意の宛先に配信） | **必要。** 朝と夕方の配信 |
| **エージェントループ**（SKILL.md の散文を読んで手順を判断） | 曖昧な質問に答えるなら必要。定型入力には過剰 |
| **スキルが散文であること**（2つ目のドメインが markdown 1枚で足せる） | 「家をきれいにしたい」等を後で足すなら効く |
| セッションを越えた記憶 | **不要。** SQLite がその役割を担っている |
| 端末バックエンド（Docker/SSH/Modal…） | 不要 |

**「記憶」と「学習」は Hermes の売りだが、この用途では SQLite と診断ルールが
既にその具体形を担っている。** 残る価値はゲートウェイと cron、そして
「曖昧な入力を解釈して正しいコマンドに落とす」層。

---

## 3つの選択肢

### 案A — Hermes を使う

```
Discord ⇄ Hermes ゲートウェイ ⇄ エージェント ⇄ SKILL.md ⇄ health CLI ⇄ SQLite
                                    ↑ cron(blueprint)
```

- 書くもの: `SKILL.md` 3枚 + Hermes の設定
- **すべての Discord メッセージがエージェントの1ターンになる**（後述のコスト参照）
- 2つ目のドメインは markdown 1枚で足せる

### 案B — 素の Discord bot（Hermes を使わない）

```
Discord ⇄ discord.py bot ⇄ health CLI ⇄ SQLite
              ↑ systemd timer / cron       ↳ 自由入力だけ Haiku を1回呼ぶ
```

- 書くもの: bot 約200行 + cron 3本
- **定型入力（`w 64.2`）は API を呼ばない = 無料**
- 曖昧な質問（「来週の旅行中どうすればいい？」）には答えられない
- 2つ目のドメインは bot のコードを書き足すことになる

### 案C — 素の bot ＋ 逃げ道

素の bot で9割を処理し、解釈できないメッセージだけ LLM に渡す。
ただし「LLM に手順とツールを渡して判断させる」を自分で書き始めた時点で、
**それは Hermes の再実装**になる。案Cは案Bと案Aの間で必ず案Aに漂着する。

## コストの比較（実装後に改訂）

**当初の見積りは前提が間違っていた。** 実装して分かったこと:

`hermes cron create --no-agent --script <path>` は
**「LLM を完全にスキップして、スクリプトの stdout をそのまま配信」**する
（`--deliver discord` も標準対応）。つまり**出力側は全部トークン0円で作れる。**

実測で確認済み（`~/.hermes/cron/output/` に `Mode: no_agent (script)` で記録が残る）。

| | LLM を通るか | 月額 |
|---|---|---|
| **出力**（朝07:00 / 夕18:00 / 日曜21:00） | **通らない** | **$0** |
| 入力・定型（`w 64.2`） | 通らない（スキルが「解釈せず実行」を指示） | $0 |
| 入力・雑な記録（自由文） | Haiku 1回 | 約$0.0045/件 |
| 入力・曖昧な質問 | エージェント1ターン | 約$0.017〜$0.10/件 |

**コスト構造が「案A対案B」ではなく「入力の種類ごと」に変わった。**
案Aを選んでも、通知と定型入力は無料。課金されるのは自由文と質問だけ。

$41 のクレジットで、1日10メッセージ（うち自由入力3・質問1）なら
**おおよそ4ヶ月〜1年**。当初の「$41では0〜1ターン」は
トークン数と金額を読み違えた誤りだった。

> **未検証の前提**: Hermes が `cache_control` を設定するかは未確認。
> ただし通知と定型入力が無料になったので、影響範囲は「質問」だけに縮んだ。

## 判断

**案A（Hermes）を推す。** ただしコストの理由ではない。

1. **元の目的は健康管理ではなく「生活のアシスタント」だった。**
   「家をきれいにしたい」は却下ではなく保留にしてある。2つ目のドメインが来たとき、
   案Bは bot にコードを足す作業、案Aは markdown 1枚。ここで差が開く
2. **曖昧な質問に答えられるかどうかが、続くかどうかを分ける。**
   「今日何すればいい？」「あと何食べればいい？」は定型化できるが、
   「明日出張だけど何を買っておけばいい？」は定型化できない
3. **案Cは必ず案Aに漂着する。** 自分で書くと Hermes の再実装になる

**そして重要な点: どちらを選んでも `health` CLI は無駄にならない。**
Hermes スキルは散文であって、実処理はこの CLI を呼ぶだけ
（優勝作 Mom-n-Pop の `crm-lite` も同じ構造）。**CLI が資産、外側の層は差し替え可能。**
だからフェーズ0を先に作ったのは、この判断を後回しにできる形になっていた。

### 案Aの前提条件

- Hermes 本体の導入（未実施）
- Discord bot トークン
- **常時稼働ホスト。** WSL2 は常時稼働ではないので、PC を閉じると送信も受信も止まる。
  月700円程度のVPSが必要。推論は Claude API に投げるのでGPUは無関係、1GB で足りる

## 入力の設計

Discord に来るメッセージを3種類に分ける。**種類ごとに通る経路を変える**のがコスト設計の要。

| 種類 | 例 | 経路 | コスト |
|---|---|---|---|
| **1. 定型** | `w 64.2` / `bp 40 8,8,8` / `today` | CLI に直通。**エージェントを通さない** | $0 |
| **2. 雑な記録** | 「ベンチ40キロ8回3セット。昼はパン3つ」 | `health nl` 相当（Haiku 1回） | 小 |
| **3. 質問** | 「あと何食べればいい？」「明日出張だけど？」 | エージェント（Sonnet） | 大 |

**1をエージェントに通さないことが最大の節約。** Hermes のスキルには
「先頭が既知のコマンド形式なら、解釈せずそのまま実行する」と明記する。

### 入力の受け皿

- チャンネルは分けない。**1つのチャンネルに全部投げる**（分けると投げる前に迷う）
- 返信は必ず1行以上返す。**無反応が最悪**（入ったのか分からないと次から投げなくなる）
- 訂正は `undo`。打ち間違いを消せないと、記録が汚れるのが嫌で入力自体をやめる

## 出力の設計

Discord の制約: 1メッセージ2000文字、画像は添付可、埋め込み(embed)は整形が効く。
**HTMLダッシュボードは Discord にインライン表示できない。** 出力はテキストに寄せる。

| 時刻 | 内容 | 長さ |
|---|---|---|
| **07:00** | 今日のメニュー。今日の分割・種目と目標重量・食事の目安・体重測定の催促 | 15行程度 |
| **18:00** | 不足通知。「あと900kcal、タンパク質45g」＋買うものの具体名 | 5行程度 |
| **日曜21:00** | 週次レポート。体重の週平均と目標補正、停滞の指摘、次週の方針 | 20行程度 |

**通知は3本まで。** 増やすと無視される習慣がつき、チャンネル全体が信用を失う。

出力の書き方は `~/health/today.txt` で試した形を踏襲する（実使用でわかったこと）:

- **数値の羅列を避ける。** `47kg × 10,10,8` ではなく `47kg で 10回 → 10回 → 8回`
- **集計値をそのまま出さない。** `1431kcal / P121g` より「ぜんぶ食べれば目標に届く」
- 表を使わない（スマホで崩れる）。1行を短く保つ
- 時間順に並べる（朝 → 買い物 → ジム）
- **CLIコマンドを出力に混ぜない。** 打つのは別の場所

| 案 | 評価 |
